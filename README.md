# AWS-Dice

A simulator of weighted dice and decks of AWS services. The project has four parts:

1. **Data analysis (Python / Jupyter):** processes a dataset of cloud architectures, computes which services appear together, and designs a set of dice whose faces are AWS services.
2. **Mobile / web app (Expo / React Native):** simulates those dice and decks on screen.
3. **3D models of the dice (STL):** ready-to-print files for the physical dice.
4. **Interview protocol:** the research protocol used to evaluate the dice with students.

### Root

| File / folder | Contents |
|---|---|
| `preprocessing.ipynb` | Loads the services catalog and the architecture graphs, normalizes them, computes service co-occurrences and transitions, and exports everything to `output_analytics/`. **Run this first.** |
| `diceMaker.ipynb` | Reads what `preprocessing.ipynb` produced, computes each service's centrality, detects incompatible services, builds the dice by category, assigns physical faces (d6 / d12), simulates 1000 rolls to validate the result, and exports the final report. |
| `data/` | Input data (see below). |
| `dice/` | STL models of the physical dice (see below). |
| `interview/` | Research protocol for the student sessions (see below). |
| `output_analytics/` | Notebook outputs (see below). |
| `AWS_Dice_Movil/` | App source code. |

### `data/`

| File / folder | Contents |
|---|---|
| `graphs/` | Example architectures in `.graphml` format (nodes = services, edges = flows between them). |
| `services.csv` | Services catalog: name, `capability`, `is_aws` flag, and AWS product categories (`aws_product_categories`). |
| `services.xlsx` | The same information as `services.csv` in Excel, for easier editing. |

### `dice/`

3D models for printing the physical dice. One file per category; the number in parentheses is the number of faces.

| File | Die |
|---|---|
| `Dado_Compute(D12).stl` | Compute, 12 faces |
| `Dado_Networking(D12).stl` | Networking, 12 faces |
| `Dado_Database(D6).stl` | Database, 6 faces |
| `Dado_Integration(D6).stl` | Integration, 6 faces |
| `Dado_Storage(D6).stl` | Storage, 6 faces |

The face-to-service assignment for each die is in `output_analytics/faces_centrality.csv`. Open the `.stl` files in any slicer (Cura, PrusaSlicer, Bambu Studio, etc.) to print them.

### `interview/`

Contains the research protocol *Evaluation of Usability and Experience in Configuring AWS Architectures*, in Word (`.docx`) and PDF formats.

### `output_analytics/`

| File | Contents | Generated by |
|---|---|---|
| `cloudscape_architectures.csv` / `.parquet` | One row per architecture (name, link, categories, number of nodes and edges). | `preprocessing` |
| `cloudscape_nodes.parquet` | All nodes (services) from all architectures, enriched with the catalog. | `preprocessing` |
| `cloudscape_edges.parquet` | All connections between services. | `preprocessing` |
| `cloudscape_pipeline_bundle.pkl` | Bundle with the full analysis state (dataset, master table, co-occurrences, graph). This is what `diceMaker.ipynb` reads. | `preprocessing` |
| `services_master_optimization.csv` | Per-service master table: popularity, base probability weight, degree, and source/sink ratio. | `preprocessing` |
| `services_cooccurrences.csv` | How many times each pair of services appears in the same architecture, plus Jaccard similarity. | `preprocessing` |
| `services_transitions.csv` | Empirical transition probabilities between services. | `preprocessing` |
| `faces_centrality.csv` | **Final result:** which service goes on each die and how many faces it takes. | `diceMaker` |

| `faces_v4_centrality.csv`, `report_v4_centrality.csv` | Results from an earlier run. The current notebooks do not generate them; delete or rename them if you no longer need them. | none |

## Running the analysis (notebooks)

Requirements: Python 3.10 or newer.

```bash
pip install jupyter polars pyarrow numpy networkx matplotlib
```

Open Jupyter **from the repository root** (paths are relative) and run the cells in order:

1. `preprocessing.ipynb` generates the files in `output_analytics/`.
2. `diceMaker.ipynb` generates `faces_centrality.csv` and `report_centrality.csv`.

If you change the dice, update `DISTRIBUTIONS` in `src/app/simulator.tsx` with the new results.

## Running the app

Run all commands inside `AWS_Dice_Movil/AWSDice/`. Requirement: [Node.js](https://nodejs.org) 18 or newer.

```bash
cd AWS_Dice_Movil/AWSDice
npm install
```

### On your phone (development)

```bash
npx expo start
```

Scan the QR code with the **Expo Go** app, or press `a` to open an Android emulator.

### On the web

```bash
npx expo start --web
```

It opens at `http://localhost:8081`.

If a web dependency is missing:

```bash
npx expo install react-dom react-native-web @expo/metro-runtime
```

## Building an APK with Android Studio

Requirements: [Android Studio](https://developer.android.com/studio) (with the Android SDK) and JDK 17.

1. Install the dependencies:

   ```bash
   cd AWS_Dice_Movil/AWSDice
   npm install
   ```

2. If the `android/` folder does not exist, generate it:

   ```bash
   npx expo prebuild --platform android
   ```

3. In Android Studio, choose **File > Open** and select the `AWS_Dice_Movil/AWSDice/android` folder. Wait for the Gradle sync to finish.
4. Open **Build > Select Build Variant** and set the `app` module to **release**.
5. Choose **Build > Build App Bundle(s) / APK(s) > Build APK(s)**.
6. When the build finishes, the APK is at:

   ```
   AWS-Dice/AWS_Dice_Movil/AWSDice/android/app/build/outputs/apk/release/app-release.apk
   ```

Copy that file to your phone and open it to install it (you may need to allow installs from unknown sources).

> With the default setup, Expo signs the release build with a debug key. That is fine for installing and testing, but to publish on Google Play you need your own signing key (**Build > Generate Signed App Bundle / APK**).
